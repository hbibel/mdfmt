# MD012 Blank Lines Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Add MD012 configured blank-line diagnostics and meaning-preserving fixes.

Architecture: Classify source lines using parsed code/front-matter regions;
count upstream JavaScript-whitespace blank runs, including the virtual EOF line.
Propose localized deletions for excess blank lines, then reparse and discard
repairs that change protected source or the semantic block tree. Run before
reflow and final-newline insertion, composing staged edit coordinates.

Tech Stack: Existing Rust source/edit pipeline and pinned markdownlint oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, MD012's conditional
repair policy in `docs/compatibility/rules.json`, pinned `lib/md012.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Continue on main without worktrees or approval interruptions, as requested.

## Review Focus

- A final virtual blank line contributes to upstream's count; EOF edits must not
  invent extra blank lines or remove protected code/table source.
- The pinned schema requires `maximum >= 1` even though the source accepts zero;
  preserve existing schema validation and stable interaction with MD047.
- Blank-run deletion between list items, paragraphs and code can change block
  meaning even if only whitespace is removed; semantic validation must reject it.
- Front matter consumes trailing blank lines per the shared discovery model;
  those lines must not be diagnosed as Markdown blank runs.
- Inline permissions, UTF-16 spans, BOM and mixed line endings must remain correct
  after earlier heading edits and later reflow.
