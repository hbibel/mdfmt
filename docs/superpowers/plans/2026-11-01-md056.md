# MD056 Table Column Diagnostics Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Report inconsistent table cell counts while preserving every table byte.

Architecture: Retain source-positioned table snapshots through the shared
diagnostic flow/container recovery. Compare actual source cells with the first
row's count per table, including disabled rows in inference. Report source-backed
missing/extra-cell ranges; never add, delete or rewrite table cells.

Tech Stack: Existing Rust source/parser/configuration pipeline and pinned oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, diagnostic-only MD056
inventory entry and pinned `lib/md056.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Must be idempotent: formatting the result again produces identical output.
- Continue inline on main without worktrees or routine approval pauses.

## Review Focus

- First-row counts reset per actual table; disabled headers/rows do not change
  inference, and nearby prose or separate tables do not merge counts.
- Escaped pipes and pipes inside code spans follow GFM table-cell source rules;
  do not infer cell count from rendered inline text or a naive string split.
- Empty/short/extra-cell rows retain their original bytes; missing-cell ranges
  point to the physical row end and extra-cell ranges include dropped data.
- Quotes/lists, generic HTML recovery and math/code exclusions retain real table
  ownership and complete source provenance, not truncated diagnostic fragments.
- Unicode/BOM/CRLF/tabs, directives, severity, fix:false and final diagnostics
  must remain source-backed without rewriting tables or second-pass changes.
