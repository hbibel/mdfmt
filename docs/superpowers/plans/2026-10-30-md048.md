# MD048 Conditional Fence Style Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Diagnose configured code fence styles and convert them only while retaining
literal code, info strings and enclosing container ownership.

Architecture: Inspect source-aware fenced code opening/closing marker spans.
Convert marker characters together, lengthening beyond any target-character run
in the body when necessary. Validate exact code AST values and other protected
source, composing original-coordinate edits through the existing pipeline.

Tech Stack: Existing Rust parser/edit/configuration pipeline and pinned oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, conditional MD048
classification in `docs/compatibility/rules.json`, pinned `lib/md048.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Must be idempotent: formatting the result again produces identical output.
- Continue on main without worktrees or approval pauses, as requested.

## Review Focus

- Target fence markers in literal code must not close a converted block early;
  choose a fence longer than every target-character run in the body.
- Backtick info strings cannot contain backticks; preserve a tilde block when
  conversion would invalidate its original language/meta spelling.
- Closing markers, opening markers and disabled source lines form one repair;
  do not rewrite an enabled opening while its closing line is protected.
- Consistent style follows the first parsed opening fence, even if that line's
  finding is disabled; indented literal fence-like text does not set the style.
- Containers, BOM/CRLF, unterminated fences and other rules must retain exact
  literal code, original edit coordinates and second-pass stability.

## Task 1: Fence findings, conditional repairs and evidence

`docs/compatibility/md048.md`; modify pipeline, specialized parser equivalence,
coverage/help, README, inventory coverage and roadmap status.

`md048::diagnose(&Source, &ParsedDocument, &DocumentConfig) -> Vec<Diagnostic>`.
Add an explicit fence-style equivalence helper only for marker-only edits;
generic protection for code must not be weakened for unrelated rules.
