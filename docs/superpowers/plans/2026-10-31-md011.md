# MD011 Reversed Link Diagnostics Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Report reversed link syntax without converting literal prose to links.

Architecture: Match pinned physical-line source patterns and source escapes with
the existing Rust regex engine. Reuse source-backed flow exclusions and a
diagnostic-only math/text parse for code/math inline overlap. No proposal stage:
reordering link delimiters changes document meaning.

Tech Stack: Existing Rust regex/source/parser/configuration pipeline and pinned
development oracle; no new runtime dependencies.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, MD011 conditional
inventory entry and pinned `lib/md011.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Must be idempotent: formatting the result again produces identical output.
- Continue inline on main without worktrees or routine approval pauses.

## Review Focus

- Reversed delimiters can be intentional literal text; do not silently create
  links, destinations or reference definitions under an automatic fix.
- Consumed preceding characters, adjacent candidates and escape/backslash endings
  must reproduce pinned non-overlapping source matching and exclusions.
- Inline code and inline math can cross physical lines; any overlapping literal
  span excludes the whole candidate, not only a match beginning within it.
- Code/HTML/math flow and front matter retain actual container boundaries;
  inline HTML does not exclude entire lines or ordinary visible text.
- Unicode/BOM/CRLF coordinates, directives, severity, fix:false and prose reflow
  must produce stable final-output diagnostics without new link structure.
