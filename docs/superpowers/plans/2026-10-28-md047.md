# MD047 Final Newline Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Implement configured MD047 final-newline diagnostics and safe repairs as
the next milestone 5 rule.

Architecture: Match the pinned parser-independent final-line check, including
its comment/blockquote blank-line exceptions. Propose an EOF insertion only
when the last source region is not an unterminated literal, metadata or table.
Validate exact authorized insertion alongside heading edits and reflow.

Tech Stack: Existing Rust toolchain and source-aware parser; pinned Node oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`,
`docs/compatibility/rules.json` MD047 preservation policy,
pinned `markdownlint/lib/md047.mjs` and `helpers/helpers.cjs:isBlankLine`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Work on main without creating worktrees and continue without approval prompts.

## Review Focus

- Empty files, whitespace, quote markers, and comments use upstream's blank-line
  exceptions, not a blanket missing-newline test.
- BOM/front matter and CRLF/lone-CR inputs must retain source coordinates and
  the most recent source newline convention.
- Fenced/indented code, raw HTML, metadata and table EOF boundaries must not grant
  arbitrary writes inside protected content.
- Inline disable directives and disabled fixes must gate repairs independently
  of configured remaining findings.
- MD013 joins and MD026 suffix deletions must not collide with EOF insertion or
  weaken their validation.
