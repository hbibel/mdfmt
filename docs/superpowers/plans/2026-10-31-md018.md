# MD018 Missing ATX Separator Diagnostics Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Diagnose missing ATX separators without converting literal text to headings.

Architecture: Match pinned root physical-line checks, excluding code, HTML flow,
math flow and front matter. Reuse original-byte/UTF-16 diagnostics and existing
permissions. No automatic separator insertion: it changes Markdown structure.

Tech Stack: Existing Rust source/parser/configuration pipeline and pinned oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, MD018 conditional
inventory entry and pinned `lib/md018.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Must be idempotent: formatting the result again produces identical output.
- Continue inline on main without worktrees or routine approval pauses.

## Review Focus

- Missing-space candidates are literal root-line text, not necessarily actual
  headings; do not silently convert meaning to mimic upstream automatic fixes.
- Arbitrarily long hash prefixes, closing hashes and the keycap emoji exception
  follow pinned source checks rather than a six-level AST heading assumption.
- Ignore physical lines owned by code, HTML flow, math flow and front matter;
  inline HTML is not permission to suppress the entire line.
- Root column-one matching must not invent findings inside indented/list/quote
  text; tabs/BOM/CRLF and Unicode must retain valid original byte spans.
- Directives, severity, fix:false and final-output reflow may affect line
  eligibility; reporting must remain stable on the formatted output.
