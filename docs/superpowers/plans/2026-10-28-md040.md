# MD040 Fenced Language Diagnostics Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Report missing/disallowed fence languages and forbidden extra info without
guessing languages or deleting source attributes.

Architecture: Read fenced code opening lines through the source-aware diagnostic
parse. Keep raw ASCII-delimited language/meta tokens, evaluate line permissions
and emit final-output findings without proposing edits.

Tech Stack: Existing Rust parser/configuration/diagnostic pipeline and pinned
development oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, diagnostic-only MD040
classification in `docs/compatibility/rules.json`, pinned `lib/md040.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Continue on main without worktrees or approval pauses, as requested.

## Review Focus

- Allowed languages match raw source tokens case-sensitively; do not borrow
  MD010's case-insensitive ignored-language matching or decode entities.
- Unicode whitespace remains part of the raw language token; ASCII space/tab
  separates info/meta, including container prefixes and tab-expanded boundaries.
- A disallowed language and extra metadata can produce two findings on one line;
  do not collapse them or guess one takes precedence.
- Indented literal code is not a fenced block; quoted/list and unterminated
  fences still receive their configured language checks.
- Rule permissions apply to the opening fence's original source line, while
  diagnostics after other repairs refer to final-output positions.
