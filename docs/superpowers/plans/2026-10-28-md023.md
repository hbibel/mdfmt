# MD023 Heading Indentation Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Diagnose heading indentation and remove it only when container ownership
and Markdown meaning remain unchanged.

Architecture: Derive line-prefix spans from parsed heading/container source,
matching pinned token-line behavior rather than stripping every leading space.
Validate deletion batches semantically and compose them before prose reflow.

Tech Stack: Existing Rust parser/edit pipeline and pinned development oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md` and MD023's conditional
classification in `docs/compatibility/rules.json`; pinned `lib/md023.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Continue on main without worktrees or approval pauses, as requested.

## Review Focus

- Blockquote optional separator whitespace is not always a heading prefix;
  preserve quote structure and match pinned diagnostic spans.
- List marker padding and continuation indentation belong to the container;
  do not remove them as though every heading were at document root.
- Setext headings can span several text lines; upstream line-prefix findings
  must not be generalized to the underline or every continuation line.
- Heading edits can interact with whitespace/reflow and line-scoped directives;
  settling must preserve permissions and second-pass stability.
- Tab-expanded source must remain diagnostic-only where native container/code
  boundaries are uncertain, including cross-rule edits in the same document.
