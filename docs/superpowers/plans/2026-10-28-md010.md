# MD010 Hard Tabs Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Add configured MD010 hard-tab diagnostics and meaning-preserving repairs,
including overlapping MD010/MD009 edits with original-coordinate reporting.

Architecture: Compose validated rule stages through original/inserted text pieces,
not assumptions about deletion-only or disjoint edits. Match pinned tab-run,
code-range and language-exclusion semantics using the read-only diagnostic parse.
Settle tab replacements and incidental trailing-whitespace deletions together
before later formatting stages; preserve literal source and uncertain prefixes.

Tech Stack: Existing Rust parser/edit pipeline; pinned Node development oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, MD010 conditional
repair classification in `docs/compatibility/rules.json`, pinned `lib/md010.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Continue on main without worktrees or approval pauses, as requested.

## Review Focus

- Tab expansion can create trailing spaces that MD009 deletes; compose overlapping
  stage edits and settle both rules instead of requiring another invocation.
- Zero spaces per tab can join words or Markdown syntax; non-code does not imply
  safe substitution. Whole-document semantic validation must reject meaning changes.
- Code-range overlap, fenced delimiter lines and ignore-code-language filtering
  follow pinned source semantics, including unintuitive option interactions.
- Tabbed container prefixes remain unsafe to rewrite even when a particular
  space multiplier happens to resemble visual tab expansion.
- Huge configured multipliers must not allocate unbounded replacement strings;
  preserve input and report remaining findings when the repair budget is exceeded.

## Task 1: General staged edit composition

Files: Create `src/edit/compose.rs`; modify `src/edit.rs`, `src/lib.rs` and tests.

Interfaces: `edit::compose_edits(original: &str, prior: &[Edit], next: &[Edit])
-> Result<Vec<Edit>, ProcessingError>`. `next` uses coordinates in the output of
`prior`. Exported edits use original coordinates; composite origins are sorted
rule IDs joined with `+`. Existing single-rule origins remain unchanged.
