# MD003 Heading Styles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Report configured heading styles and convert heading delimiters only where heading levels, content and surrounding structure survive unchanged.

**Architecture:** Extract native source-backed heading snapshots and compute target styles from pinned MD003 semantics. Propose localized delimiter edits on the native edit tree, not the diagnostic recovery tree, and require reparsing equivalence that exempts only outer heading syntax. Run after MD026, heading spacing and MD058 separators settle; report remaining findings on final output.

**Tech Stack:** Rust 1.99, existing source/parser/edit/configuration pipeline, pinned markdownlint development oracle.

**Spec:** `docs/superpowers/specs/2026-10-21-mdfmt-design.md`

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve inline links without conversion to reference links.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Keep the sibling worktree and shared parent configuration; execute inline without routine approval pauses.

## Review Focus

- A disabled first heading still sets consistent style; directives filter fixes/findings, not history.
- Pure setext cannot represent levels 3–6; preserve these headings with remaining diagnostics.
- ATX-looking content, trailing hashes and setext-adjacent paragraphs must retain text and block ownership.
- Conversions that change physical lines must not retarget any rule's line-scoped directives.
- Multiline/protected inline source, code, tables, metadata, Unicode, BOM and mixed terminators stay intact.
