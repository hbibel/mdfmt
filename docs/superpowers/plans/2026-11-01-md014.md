# MD014 Shell Prompt Diagnostics Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Report prompt-prefixed command-only code blocks without deleting code.

Architecture: Read source-positioned fenced/indented code blocks from a
diagnostic parse. Classify the complete block's nonempty code-value tokens before
permissions, then map prompt/whitespace ranges back to original bytes and UTF-16
columns. No prompt deletion: code is protected content, not an inferred command.

Tech Stack: Existing Rust source/parser/configuration pipeline and pinned oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, conditional MD014
inventory entry and pinned `lib/md014.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must report remaining violations when the effective configuration flags them.
- Must be idempotent: formatting the result again produces identical output.
- Continue inline on main without worktrees or routine approval pauses.

## Review Focus

- Any output/non-command code value suppresses findings for the complete block,
  including disabled lines; permissions do not change block classification.
- Blank/whitespace-only lines and unclosed fences must match pinned code-value
  token boundaries rather than arbitrary physical-line counts.
- Lists/quotes/fence indentation consume container padding, not literal command
  whitespace; original columns and contexts must retain the correct ownership.
- Math fences and inline code are not shell blocks; code containing math-like
  text remains ordinary code with exact source preserved.
- Tabs, ECMAScript whitespace, BOM/CRLF, directives and final-output diagnostics
  must remain source-backed without deleting prompts or second-pass changes.
