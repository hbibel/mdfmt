# MD004 Unordered List Style Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal: Add configuration-aware MD004 marker diagnostics and context-safe repairs.

Architecture: Collect direct unordered item markers from parsed list ancestry.
Match pinned global consistent and per-depth sublist selection, counting ordered
ancestors in sublist depth. Replace only marker bytes after contextual semantic
and protected-source validation; preserve separate lists and avoid accidental
thematic breaks. Compose replacements with earlier localized edits.

Tech Stack: Existing Rust parser/edit pipeline and pinned Node development oracle.

Spec: `docs/superpowers/specs/2026-10-21-mdfmt-design.md`, MD004 safe repair
classification in `docs/compatibility/rules.json`, pinned `lib/md004.mjs`.

## Global Constraints

- Must respect the effective supported markdownlint configuration.
- Must preserve content and Markdown meaning rather than force an unsafe fix.
- Must preserve tables. Violations involving tables may remain unresolved.
- Must be idempotent: formatting the result again produces identical output.
- Continue on main without worktrees or approval pauses, as requested.

## Review Focus

- Mixed markers can delimit separate lists; a repair must not silently merge
  parsed list nodes or change looseness/nesting.
- A marker replacement can turn `- * *` into a thematic break; reject that rewrite.
- Sublist style uses global depth choices, counts ordered-list ancestors, and
  cycles dash → plus → asterisk → dash when a child matches its parent style.
- Disabled source markers still establish consistent/depth style, while their
  own fixes and diagnostics remain suppressed by permissions.
- Task checkboxes, quotes, tabs, BOM/CRLF and earlier reflow must preserve source
  coordinates and protected code/table content.
