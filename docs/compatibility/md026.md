# MD026 heading punctuation

MD026 is implemented natively against markdownlint 0.42.0's `lib/md026.mjs`
and its entity/emoji helper patterns. Node is a development oracle, not a runtime
dependency. Coverage is still incomplete: MD013, MD026 and MD047 are implemented.

## Behavior

- Enabled by default, with punctuation `.,;:!。，；：！`; question marks are allowed.
- Respects custom punctuation, empty sets, aliases/tags, severity, inline directives,
  `enabled: false`, and both API/configuration fix permissions.
- Matches raw ATX/setext heading text, not rendered text. ATX closing markers and
  surrounding whitespace remain intact. Setext trailing whitespace prevents a
  match, as upstream does. Only the last line of multiline setext text is edited.
- Preserves suffixes recognized by the pinned entity/emoji patterns. These are
  syntax patterns, not registries of valid names. An entity followed by additional
  punctuation is not exempt: `&amp;!` loses `;!`, as upstream prescribes.
- Produces remaining MD026 findings when fixes are disabled. Diagnostics use
  output byte spans and CLI UTF-16 columns, excluding a leading BOM.
- Permits exact configured heading deletions through generic heading protection.
  Other edits retain strict protection. Heading fixes settle against reparsed
  source before MD013 selects and validates prose gaps. Returned edits retain
  original source coordinates across these stages.

## Evidence

`tests/md026.rs` runs all seven approved MD026 acceptance examples, literal
regressions, and 440 recorded upstream observations for raw boundaries,
configuration, containers, front matter, directives, Unicode, CRLF and exceptions.
Every recorded fix is checked for a stable second pass. CLI tests cover stdout,
check/write, disabled fixes, error/warning exits and MD013 interactions.

Reproduce runtime comparisons after building the CLI:

```sh
mise exec -- cargo build
node tools/parser-oracle/md026.mjs
```

The oracle verifies both disabled-fix findings and converged upstream fixes.
`--record` updates the checked-in upstream receipt. It strips the BOM before
calling upstream's `applyFixes` because lint coordinates exclude the BOM.

## Policy differences and limits

Upstream can require several passes for whitespace-separated suffix punctuation.
mdfmt settles repeated prescribed deletions in one pass for idempotence.

Pinned upstream throws an invalid-range exception for `First\n!\n---\n` because
its whitespace match crosses lines. mdfmt confines suffix matching to the final
content line instead of copying the crash or deleting container prefixes.

CommonMark/GFM parser limitations described in the parser evaluation still apply;
this is not a claim of full upstream extension equivalence. Custom astral
punctuation is handled as Unicode scalars, not JavaScript surrogate halves, to
avoid producing malformed UTF-8.
