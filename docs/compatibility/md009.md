# MD009 trailing whitespace

MD009 diagnostics and conditional incidental-whitespace repairs follow
markdownlint 0.42.0's `lib/md009.mjs`. Overall rule coverage remains incomplete;
see `rules.json`.

## Behavior

- Matches source JavaScript `trimEnd` whitespace and UTF-16 counts, not just ASCII
  spaces. `br_spaces` defaults to 2; values below 2 mean zero permitted suffix units.
- Implements configured strict, code-block and list-item-line exceptions. Fenced
  delimiter lines are checked separately from interiors, matching pinned token
  boundaries, including unterminated fences at EOF.
  A quoted unterminated fence ends at its container's last physical line; root
  and ordinary list fences can include the virtual EOF line in that boundary.
- In strict mode, an otherwise permitted suffix count still requires a paragraph
  continuation outside multiline inline code.
- `list_item_empty_lines` follows pinned source semantics: normal item-content
  lines are also exempt, while trailing indent lines outside the item's final
  content are not. Empty quote-prefix lines inside item content remain exempt.
  Runtime evidence covers these distinctions.
- Respects aliases/tags, severity, directives and fix permissions. Findings refer
  to final-output byte spans and CLI UTF-16 columns, excluding an initial BOM.
- Whitespace and heading deletions settle together before blank-line repairs
  and reflow, including newly exposed prose after setext-heading removal. Active line-scoped
  MD009 overrides prevent reflow from shifting the source text they disable.

## Preservation limits

Upstream deletes every flagged suffix, sometimes removing a meaningful hard
break or code content. Native repairs do not: code, headings, tables, metadata,
hard breaks and other protected spans remain unchanged. Removing whitespace
must also preserve the parsed structure, so a deletion cannot expose an escaped
hard break or strip meaningful non-breaking whitespace.

After protected candidates are filtered, a failed semantic check withholds the
remaining batch. Unmodeled HTML/math/directive documents and uncertain tabbed
container prefixes also retain their bytes. Unresolved configured findings remain.

Code/list/paragraph diagnostic classification uses the shared read-only tab-
expanded parse when needed; suffix counts and reported spans still use original
source. Existing parser-extension limitations remain explicit.

## Evidence

`tests/md009.rs` covers literal repairs, protected hard breaks/content, options,
Unicode/BOM/CRLF, severity, fix permissions, line-scoped reflow interactions and
all-rule original edit reconstruction/idempotence. It compares findings with 500
pinned runtime cases. CLI tests cover stdout/check/write and remaining hard-break
errors versus disabled-fix warnings.

```sh
mise exec -- cargo build
node tools/parser-oracle/md009.mjs
```

The development oracle checks native findings and second-pass stability. In the
recorded corpus, 182 native outputs intentionally preserve source upstream would
delete. Literal tests establish the preservation reasons; no claim of identical
automatic-fix output is made. Node is not a runtime dependency.
