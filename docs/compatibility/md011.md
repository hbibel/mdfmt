# MD011 reversed-link syntax

MD011 reports reversed `(text)[destination]` syntax without reordering delimiters.
The upstream automatic fix creates link structure from literal text, so native
retains the source and reports configured findings. Overall coverage is partial;
the reference is markdownlint 0.42.0's `lib/md011.mjs`.

## Behavior

Physical-line matching follows pinned non-overlapping regex behavior, consumed
preceding characters, escaped openings and escaped closing content, empty groups,
caret-prefixed destinations and following-parenthesis exclusions. Findings cover
only the reversed candidate, not its consumed preceding character, with original
byte spans and UTF-16 positions. Error detail retains the candidate text.

Code, HTML flow, math flow and front matter are excluded using shared literal
exclusions. Any overlap with inline code or inline math excludes a whole
candidate, including multi-line literal spans and spans recovered after generic
HTML/container boundaries. Inline HTML does not exclude ordinary visible text.

The optional diagnostic-only parser enables math flow and text; the formatting
parser and its existing math preservation guard remain unchanged. With no enabled
candidates, no literal-exclusion parse is performed. Existing native parser
limits remain; full upstream parser parity is not claimed.

Aliases/tags, inline directives, warnings and fix permissions are respected.
Diagnostics describe final output after any configured prose reflow. The rule
never edits delimiters or invents destinations.

## Evidence

`tests/md011.rs` covers source matching, escapes/adjacency, flow and inline
literal exclusions, recovered HTML boundaries, Unicode/BOM/CRLF, permissions,
CLI modes and reflow stability.

```sh
mise exec -- cargo build
node tools/parser-oracle/md011.mjs
```

The oracle passes 126 pinned/native diagnostic and source-preservation cases;
38 upstream automatic-fix outputs differ because native preserves meaning.
Node is not a runtime dependency.
