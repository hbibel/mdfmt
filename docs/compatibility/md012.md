# MD012 blank lines

MD012 diagnostics and conditional repairs are implemented natively against
markdownlint 0.42.0's `lib/md012.mjs`. Current rule coverage is MD012, MD013,
MD026 and MD047 only; successful processing is not full markdownlint compliance.

## Behavior

- Enabled by default; `maximum` defaults to 1. The pinned schema requires at
  least 1. Although the upstream source accepts 0, native configuration continues
  to reject it according to the existing schema contract.
- Counts JavaScript-whitespace blank lines, including the virtual blank line
  after a final newline. Quote markers and comments are not whitespace for MD012.
- Excludes parsed fenced/indented code and recognized front matter, including
  trailing blank lines consumed by the shared front-matter pattern.
- Respects aliases/tags, severity, rule/fix disabling and inline directives.
- Settles safe blank-line deletions before prose reflow and final-newline repair.
  Returned edits use original source coordinates across all stages.
- Reports remaining findings on the final output, including preserved source.

## Safety boundary

Every proposed batch must preserve the semantic parse and exact protected source.
List looseness or other block changes can therefore prevent repairs. Parser
differences around Unicode whitespace can also prevent deleting a lint-blank
line that the parser treats as content. The whole blank-line batch is withheld
when validation fails; diagnostics remain.

Documents with non-comment HTML or conservatively recognized math/directive
syntax retain their blank lines until those boundaries are modeled. Exact
source-permission checks may preserve blank lines immediately next to an inline
directive. Tables, code and metadata source are not rewritten to force a fix.

## Evidence

`tests/md012.rs` covers literal outputs, limits, BOM/CRLF, code/front matter,
preservation, permissions, severity, combined-rule idempotence and original edit
coordinates. It checks findings against 125 recorded pinned observations,
including explicit native rejection of maximum-zero configurations. CLI tests
exercise stdout/check/write and disabled-fix warning diagnostics.

```sh
mise exec -- cargo build
node tools/parser-oracle/md012.mjs
```

The development oracle checks diagnostics, safely actionable outputs and schema
errors. Its preserved-source cases are explicit; no general upstream parser
equivalence is claimed. Node is not a runtime dependency.
