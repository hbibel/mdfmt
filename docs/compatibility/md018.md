# MD018 missing ATX separators

MD018 reports missing spaces after opening hashes while preserving literal text.
Inserting the upstream space can create a heading, changing document structure;
this batch reports findings without making that meaning-changing edit. Overall
built-in coverage remains partial. The reference is markdownlint 0.42.0's
`lib/md018.mjs`.

## Behavior

Candidates begin at physical column one with one or more hashes followed by a
character other than a hash, space or tab. The source check is not restricted to
the six valid heading levels. Closed-hash endings and the hash-keycap emoji have
the pinned exceptions. Indented and list/quote-prefixed candidates are not
invented by stripping container syntax.

Code, HTML flow, math flow and front matter are excluded. Inline HTML does not
exclude its whole line. Root math fences follow the pinned minimum dollar count,
metadata and closing-fence rules. Diagnostic-only neutralization prevents code
or HTML inside math from leaking native exclusions past the math's closing fence.
This is a targeted source-line adapter, not general upstream parser parity.

Directives, aliases/tags, warnings and fix permissions are respected. Findings
describe the final output, including when MD013 reflows surrounding prose.
Diagnostic context uses pinned trimming and UTF-16 truncation. Spans use original
bytes; when upstream ends a range inside an astral character's surrogate pair,
the native range includes that complete scalar rather than an invalid byte end.
That range is one UTF-16 unit longer than the pinned range.

## Evidence

`tests/md018.rs` covers source checks/exceptions, flow exclusions, math/code/HTML
boundaries, nesting, Unicode/BOM/CRLF, permissions, reflow stability and CLI modes.

```sh
mise exec -- cargo build
node tools/parser-oracle/md018.mjs
```

The oracle passes 132 pinned/native diagnostic and source-preservation cases;
46 upstream automatic-fix outputs differ because native retains heading meaning.
Node is not a runtime dependency.
