# MD014 command-only shell prompts

MD014 diagnoses prompt-prefixed command-only code blocks while retaining code
bytes. Deleting prompt characters requires deciding whether they are literal
code or presentation, so the native rule does not apply upstream's automatic
deletion. Overall coverage is partial; the reference is markdownlint 0.42.0's
`lib/md014.mjs`.

## Behavior

Fenced and indented blocks are classified as a whole before line permissions.
Every participating code-value token must begin with optional ECMAScript whitespace,
then `$` and further whitespace. Any output/non-command value suppresses all
findings for that block, including output on a disabled line. Truly empty physical
lines do not participate; a whitespace-only code value does participate and
suppresses the block. Consuming a tab can leave an empty code-value token that
still participates, including at an unclosed fence's EOF. Missing output is
diagnosed without inventing it.

Source-positioned code snapshots retain fence/container-relative content, nested
quotes/lists, tabs, unclosed fences and original byte provenance. The shared
diagnostic literal parser also retains snapshots recovered after generic HTML
container boundaries. Container continuation indentation keeps HTML-owned text
out of eligible code snapshots; recovery follows actual root flow through blank
lines to a fence's real end. Blank separators preserve the previous container
context where its indentation still continues. Inline code and math are not shell blocks. Formatting
parse options remain unchanged; general upstream parser parity is not claimed.

Logical code snapshots now share MD046's source-ordered ownership. Native
indented-code nodes split across blank lines are joined only within the same
container and across a real blank/prefix-only gap. Adjacent nodes without a blank
and separate list items/quotes remain independent. Joined values retain physical
line distances, so output suppresses the entire logical block while command-only
findings retain their original lines and byte spans. Tab-expanded ownership keeps
original code values where available and remaps ranges to original source.

Findings span only `$` and its following whitespace using original bytes and
UTF-16 columns. Context retains code-value indentation and uses pinned truncation.
Aliases/tags, directives, warnings and fix permissions are respected. Final
diagnostics describe formatted output; this rule never edits code content.

## Evidence

`tests/md014.rs` covers whole-block classification, source-backed prompt ranges,
flow/inline exclusions, recovered root code, permissions, CLI modes and reflow
idempotence. The pinned corpus adds nested fence indentation and tab variations.

```sh
mise exec -- cargo build
node tools/parser-oracle/md014.mjs
```

The oracle passes 462 pinned/native diagnostic and source-preservation cases;
232 upstream automatic-fix outputs differ because native preserves code.
Four regression tests cover blank-container output, command contexts/offsets,
adjacent parser tokens and empty nested-container barriers. The first reproduces
the previous false positive; adjacency/barrier tests also failed before requiring
actual blank gaps and consecutive sibling ownership. The optimized full suite
passes 471 tests across 65 targets with unchanged assertions/time limits.
Node is not a runtime dependency.
