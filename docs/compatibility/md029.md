# MD029 ordered-list numbering

MD029 diagnoses configured numbering and conditionally normalizes later markers.
Every original first marker is retained, preserving rendered start values even
when the configured style flags them. Overall rule coverage remains partial.
The reference is markdownlint 0.42.0's `lib/md029.mjs`.

## Behavior

Direct item prefixes are grouped by ordered-list ownership. `one`, `ordered`,
`zero` and `one_or_ordered` follow pinned inference, including zero starts,
right alignment and zero padding. Disabled first/second markers still determine
style and subsequent expected positions. Numeric equality does not require
rewriting zero-padded spellings.

Findings cover complete source-backed item prefixes using byte spans and UTF-16
columns. Edits replace digit spans only, retaining delimiters and following
whitespace. Rule aliases/tags, inline directives, severity and fix permissions
are respected. Diagnostics describe the final output.

## Preservation and parser limits

Marker-width changes must retain list/container ownership, code values and all
protected source under whole-document validation. Unsafe batches are withheld;
MD029 does not weaken the shared preservation contract. Numbering settles before
reflow with original-coordinate edit composition and second-pass stability.

After an empty item, the native parser can incorrectly let a non-1 ordered
marker interrupt a paragraph. MD029's read-only diagnostic adapter masks the
invalid delimiter with an equal-width non-marker and reparses until paragraph
interruption is restored. Source spans still refer to original bytes. An actual
`1` interruption or a blank-separated list remains eligible. All rule edits are
withheld when this ambiguous boundary is present, including unrelated edits.
Other diagnostic rules still have native-parser limitations; this adapter does
not establish general parser parity. Structural tab uncertainty also withholds
edits; diagnostic tab expansion is never written back to source.

## Evidence

`tests/md029.rs` covers configured styles, inference, padding, nested/empty items,
rendered starts, code preservation, directives, tabs/BOM/CRLF, permissions,
cross-rule composition, CLI behavior and empty-item interruption regressions.

```sh
node tools/parser-oracle/md029.mjs
```

The oracle passes 301 pinned/native diagnostic, rendered-start/code/container
preservation and idempotence cases, with 116 intentional upstream-fix differences.
Another 500 generated diagnostic comparisons passed locally. Node is not a
runtime dependency.
