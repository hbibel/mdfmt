# MD060 table-column diagnostics

MD060 reports table spacing and alignment under markdownlint 0.42.0's
`lib/md060.mjs`. It never rewrites table rows, cells or delimiter lines.

## Behavior

- `aligned` compares each later row's pipe display columns with the header.
  Missing pipes are not invented; MD056 separately reports cell counts.
- `compact` requires one whitespace unit on each applicable side of a pipe.
  `tight` requires no padding. Edge pipes and trailing row whitespace follow
  upstream's token boundaries, including empty cells and tabs.
- `any` selects the fewest candidate findings per table, preferring aligned,
  then compact, then tight on ties. Disabled rows still participate in selection.
- `aligned_delimiter` adds header/delimiter alignment checks to compact and tight.
- Escaped pipes, code-span pipes, nested tables and recovered table continuations
  use source-backed row boundaries. Front matter, fenced code, math and HTML
  blocks are excluded where the pinned parser excludes tables.
- Aliases, inline permissions, severity and final-output positions apply normally.
  Findings remain when fixes are disabled. Warning-only findings do not fail CLI
  checks when no edit is needed.

## Display width is not source width

Diagnostic spans select original pipe bytes. Their columns count UTF-16 units,
excluding an initial BOM. Alignment instead uses the audited `string-width@8.3.0`
algorithm under Node 24.19.0, Unicode 17.0 and ICU 78.3.

The native adapter uses pinned `icu_properties@2.1.2` data and
`unicode-segmentation@1.13.3`, both targeting Unicode 17. It handles visible
grapheme bases, emoji sequences and valid flags, Hangul syllable pieces, spacing
marks, halfwidth forms and upstream's ANSI stripping. Arabic `لا` measures 2,
unmatched Hangul `ᅡ` measures 1, and tabs contribute 0. Invalid flag pairs use
their first scalar's narrow width rather than automatically measuring 2.

The flag allow-list is derived from Unicode 17's
[emoji-sequences.txt](https://www.unicode.org/Public/17.0.0/emoji/emoji-sequences.txt),
under the [Unicode license](../../src/md060/UNICODE-LICENSE.txt).

Table ownership uses a tab-expanded diagnostic parse with table, row, cell and
delimiter spans mapped back to original bytes. A tab after a list marker can
require four-space continuations; insufficient indentation must not invent a
table or fail CI checks. Expansion does not supply the display-width input.

Unlike MD033 tokenization, MD060's display prefixes use markdownlint's
comment-sanitized lines. Comment masking preserves UTF-16 units: a combining
sequence, tab or ZWJ emoji inside a comment can change its displayed width after
masking. Raw token columns and diagnostic byte ranges remain unchanged.

The pinned fixture corpus verifies these boundaries; full equivalence for every
Unicode sequence or future Node/ICU release is not claimed. Existing native
parser-extension limits remain.
The independent review found differences for 990 unassigned scalars, but no
differences across assigned scalars and 40,000 generated clusters. Reserved
code-point width parity is deferred; it is not implied by the pinned corpus.

## Evidence

`tests/md060.rs` covers 1,133 pinned cases, literal style findings, table-byte
preservation, CLI check/write/warning outcomes, permissions, reflow positions and
idempotence. The adapter's unit test compares 734 widths, including every pair
of regional indicators, against the audited runtime.
`tests/table_tabs.rs` covers the independently reviewed false-table regression
across MD055, MD056, MD058 and MD060, including successful check/write outcomes.

```sh
mise exec -- cargo test --test md060 --lib
mise exec -- cargo build
node tools/parser-oracle/md060.mjs
```

The CLI oracle checks both fix modes. Node is development-only.
