# MD013 implementation evidence

The first useful formatter path reflows eligible prose to MD013's configured
width and reports remaining MD013 violations. It is native Rust; Node is only a
development oracle. Other rules, including MD026, belong to subsequent rule batches.

## Reflow

- Greedy wrapping uses UTF-16 source widths, including list and quote prefixes.
  Exact-width lines fit. Inline links, images, code, and emphasis remain intact.
- Soft breaks join with one space before packing. Existing horizontal spaces stay
  intact when they fit. Hard-break markers and their line endings remain unchanged.
- Nested lists, ordered markers, task lists, nested quotes, mixed list/quote
  containers, and lazy continuations have regression coverage. New continuation
  lines repeat the structural prefix, not list markers or task checkboxes.
- Every source line of a paragraph must permit MD013 edits. Directives and
  partially disabled paragraphs are not joined or moved through. Disabling fixes
  leaves source unchanged but does not disable findings.
- Expanded edits must match exact modeled whitespace/container gaps. Reparsed
  output must retain a position-independent mdast tree and exact protected source;
  otherwise the document's entire reflow batch is rejected.

## Diagnostics

Native diagnostics follow the pinned markdownlint 0.42.0 MD013 source: default,
strict, and stern exceptions; heading/code widths inheriting the prose width;
category include flags; reference-definition exemptions; link/image-only lines;
front-matter exclusion; aliases, inline permissions, and severity. Findings refer
to the formatted output, not stale input positions. Default tail-token matching
uses RE2JS ASCII whitespace; stern's token test uses JavaScript whitespace.

Messages report exact configured/actual UTF-16 widths. Spans use UTF-8 byte
boundaries. If the limit splits a surrogate pair, a span covers the entire Unicode
scalar instead; the displayed column starts at that scalar. BOMs do not count
toward widths or displayed columns. Error findings cause exit 1; warnings alone
do not. Check mode also exits 1 when formatting changes are needed.

## Verification

Observed locally on 2026-10-27:

- 27 reflow input/output cases compared with the actual pinned parser and MD013,
  including second-pass idempotence and remaining findings.
- 264 native/upstream diagnostic comparisons, with receipts in
  `tools/parser-oracle/md013-observations.json` and native regression tests.
- 24 applicable MD013 acceptance examples executed as real formatter tests,
  including the unavailable-formatter examples solely as code-preservation tests.
  No external formatter execution is claimed.
- Existing protected-region, configuration, file-selection, write-safety, and CLI
  regressions remain part of the full Rust suite. A scaling smoke test exercises
  100, 500, and 1,000 paragraphs without per-edit whole-document region scans.

Reproduce from the checkout, with the pinned development dependencies installed:

```sh
mise exec -- cargo test --all-targets
mise exec -- cargo fmt --check
mise exec -- cargo clippy --all-targets -- -D warnings
mise exec -- cargo build
npm run test:reflow --prefix tools/parser-oracle
npm run test:md013 --prefix tools/parser-oracle
npm run test:reflow-scaling --prefix tools/parser-oracle
```

Run the oracle commands after building, not concurrently with a binary rebuild.
Use `node tools/parser-oracle/md013.mjs --record` only when intentionally updating
reviewed receipts; normal runs verify the existing upstream evidence first.

## Remaining boundaries

These comparisons are bounded evidence, not a claim that markdown-rs and upstream
micromark parse every extension identically. Reflow conservatively preserves
documents with non-comment HTML, or paragraph dollar/colon-letter markers that
may indicate math/directives. This can leave ordinary prose unwrapped. Paragraphs
with tabs or multiline protected inline source are also preserved. Diagnostics
use the native classification; untested upstream extensions may differ.

The library lists MD013 as implemented, with overall rule coverage incomplete.
That metadata does not assert full parser parity or implementations of the other
built-in rules. Differential corpus growth, finer preservation boundaries, and
release hardening continue on the roadmap.
