# MD024 duplicate heading diagnostics

MD024 reports duplicate heading content without renaming headings, changing
anchors or guessing a document hierarchy. The compatibility reference is
markdownlint 0.42.0's `lib/md024.mjs` and heading-text helpers. This rule is
diagnostic-only; overall built-in coverage remains partial.

## History and text matching

The default history includes every parsed heading in document order. Matching
is case-sensitive and retains raw inline spelling and significant internal
whitespace. Direct HTML tokens are omitted, while HTML nested inside emphasis
or other raw inline syntax remains part of that syntax. Entities, escapes,
links and code are not reduced to their rendered display text.
Pinned strikethrough tokens expose their direct HTML rather than forming the
same opaque wrapper as emphasis; HTML there is excluded too. Raw source between
inline children is retained, including container prefixes across setext hard
breaks, rather than reconstructing the key from disjoint child spans.
Single-line ATX keys use lexical source-caption boundaries: literal hashes remain
part of the key even when native child ranges omit them. Existing HTML filtering
and multiline setext keys retain their pinned behavior.

`siblings_only: true` scopes duplicate history by heading levels. Deeper-level
history resets when entering a new scope or returning to a shallower level,
including skipped levels. Quote/list container ancestry does not partition this
history. Disabled reference headings still populate history and affect level
transitions; their own findings are suppressed separately.

Multiline heading text uses the pinned line-ending normalization and trimming.
Empty headings can be duplicates, but empty context does not add a context suffix.
Aliases/tags, directives, severity and fix permissions are respected.

## Preservation and positions

MD024 alone never changes source in any CLI mode. Other approved repairs run
first: for example, MD026 punctuation removal can expose a duplicate in the
final heading history. Findings use empty spans at final physical line starts,
excluding a leading BOM. Context follows the pinned UTF-16 truncation limit.

Tab expansion remains diagnostic-only; raw heading text is mapped back to
original bytes. Existing parser-extension limitations remain; full upstream
parser equivalence is not claimed.

## Evidence

`tests/md024.rs` covers raw text distinctions, global/sibling history, disabled
reference headings, container/setext/empty headings, Unicode/BOM/CRLF, severity,
CLI behavior and MD026 final-history/idempotence interactions.

```sh
mise exec -- cargo build
node tools/parser-oracle/md024.mjs
```

The development oracle passes 224 pinned/native diagnostic and source-preservation
cases. Node is not a runtime dependency.
