# MD035 thematic-break styles

MD035 diagnostics follow markdownlint 0.42.0's `lib/md035.mjs`. Native repairs
go beyond upstream, which supplies no automatic fix for this rule. Overall rule
coverage remains incomplete; see `rules.json`.

## Behavior

- Enabled by default. Consistent style uses the first recognized thematic
  break, including its trailing whitespace but not container prefixes/indentation.
  A break suppressed by a per-line directive still establishes that style.
- Explicit styles follow upstream's empty-string fallback and JavaScript trimming.
  Rule disabling, aliases/tags, severity, directives and fix permissions apply.
- Only parsed thematic breaks are replaced, never setext underlines, metadata
  delimiters, table syntax or code. Leading indentation and container source remain.
- Configured style strings must consist of at least three identical `*`, `-` or
  `_` markers with optional spaces/tabs before a repair is considered. Arbitrary
  strings accepted by the schema receive diagnostics but are not injected as Markdown.
- Every replacement batch must preserve the semantic block tree and all protected
  source except thematic-break marker styles. This rejects setext conversion,
  list-structure changes and accidental creation of front matter.
- Repairs run after reflow and before EOF insertion. Original edit coordinates
  are preserved even when a style replacement changes source length or a
  preceding heading deletion exposed the thematic break.

## Limits and evidence

Documents with conservatively recognized unmodeled HTML, math or directives are
not repaired. A failed contextual check withholds the whole style batch, leaving
configured findings instead of forcing an unsafe rewrite.

`tests/md035.rs` covers literal native outputs, contextual rejection, permissions,
containers, raw whitespace, BOM/CRLF and combined-rule edit reconstruction and
idempotence. It checks disabled-fix findings against 153 recorded pinned cases.
CLI tests exercise stdout/check/write, invalid-but-declarative styles, and warnings.

```sh
mise exec -- cargo build
node tools/parser-oracle/md035.mjs
```

The development oracle compares findings before and after native repairs and
checks second-pass stability. Native fix outputs are separately asserted as
literal Rust tests; no upstream automatic-fix equivalence is claimed. Node is
not a runtime dependency, and full parser-extension parity is not claimed.
