# MD048 code fence styles

MD048 diagnoses configured fence styles and conditionally changes fence markers
without formatting literal code. The compatibility reference is markdownlint
0.42.0's `lib/md048.mjs`. Upstream reports this rule but has no automatic repair;
native repair output is an intentional extension. Overall coverage remains partial.

## Behavior

`style` supports `consistent`, `backtick` and `tilde`. Consistent style follows
the first parsed opening fence, including a disabled reference line. Indented
literal fence-like text does not set the style. Diagnostics refer to opening
lines with pinned expected/actual details, severity and permissions.

Repairs change only opening/closing marker spans, preserving info strings,
literal bodies, indentation, containers and line endings. The new opening fence
is at least three characters, its original length, and one character longer than
the longest target-character run in the body. The closing fence is at least its
original length and the new opening length.

Backtick conversion is withheld if the info string contains backticks. Conversion
is also withheld when an immediately adjacent info prefix would be absorbed into
the target marker run; the rule does not insert a new info separator. If either
changed marker span is disabled, the block remains unchanged. Aliases/tags,
directives, severity and fix permissions are respected.

## Preservation boundary

Uncertain tabbed containers and unmodeled syntax remain preserved. A lexical
closing-fence candidate is not sufficient authorization: the entire marker-only
batch must preserve parsed code values, language/meta and enclosing block ancestry.
All other protected source remains exact. A failed semantic check withholds the
batch, potentially leaving unrelated safe fence conversions unresolved too.

The specialized fence-style comparison ignores raw code-container markup only
for MD048's marker-only proposals. Generic code protection for other edit stages
is unchanged. Original body/info bytes are never edited; no external formatter
runs. Unterminated blocks can change their opening marker only when the same
semantic check succeeds; no closing fence or literal EOF newline is invented.

Fence conversion runs before EOF normalization and uses original-coordinate
stage composition. MD010/MD040 literal findings can remain after safe marker
repairs. Existing parser limits remain; full upstream parser parity is not claimed.

## Evidence

`tests/md048.rs` covers explicit/consistent styles, disabled references/closing
lines, target collisions, info constraints, containers, EOF, Unicode/BOM/CRLF,
permissions/severity, CLI modes and cross-rule edit reconstruction/idempotence.

```sh
mise exec -- cargo build
node tools/parser-oracle/md048.mjs
```

The development oracle passes 220 pinned/native diagnostic, literal-code and
idempotence cases, including 41 native marker repairs absent upstream. It also
compares upstream literal code/info tokens and container ownership before/after
native repair. Node is not a runtime dependency.
