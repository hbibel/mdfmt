# MD045 missing alternate text diagnostics

MD045 reports Markdown and HTML images missing the alternate-text requirements
of markdownlint 0.42.0's `lib/md045.mjs`. It does not invent descriptions or edit
source. Overall built-in coverage remains partial.

## Behavior

- Markdown images with empty raw labels are reported. Whitespace-only labels
  are not empty under the pinned token check; the rule does not judge quality.
- Resolved reference images, nested images and images inside links/tables are
  checked. Undefined references and literal code are not treated as images.
- HTML `<img>` tags are reported when the pinned attribute matcher finds neither
  an `alt` assignment nor `aria-hidden` with a case-insensitive `true` value.
  Empty `alt=""` is present; valueless `alt` is not an assignment.
- Attribute matching retains the pinned raw-text regular-expression semantics,
  including Unicode whitespace. This is not DOM interpretation or validation.
- Non-comment HTML flow is diagnostically reparsed as Markdown with HTML flow
  and indented-code constructs disabled, as upstream does. Apparent tags inside
  script/style strings can therefore be findings. Comments and inline code
  retain their pinned exclusions.
- Aliases/tags, directives, severity and fix permissions apply normally.

## Source and range preservation

MD045 alone never changes image, table or HTML bytes. The formatter's existing
HTML-preservation guard remains in force for other repairs. Diagnostics use a
read-only tab-expanded parse where necessary, mapping spans to original source.
Image descriptions are reparsed because native mdast flattens nested syntax into
alternate text; nested findings retain their own original positions.

Single-line Markdown images use full image spans. Multiline Markdown images
have line-only findings, represented by empty spans at line start. HTML tags use
their first physical line's span. Columns count original UTF-16 units, excluding
an initial BOM, and refer to final output after other safe repairs.

The CLI keeps its established source-position diagnostic ordering. Upstream's
rule processes Markdown images before HTML tags, so findings on one line can
appear in a different order; comparisons account for that presentation difference.
Existing parser-extension limitations remain; full upstream parser parity is
not claimed.

## Evidence

`tests/md045.rs` covers literal label/attribute cases, nested syntax, code and
HTML boundaries, Unicode/BOM/CRLF, permissions, severity, CLI modes and final
positions after safe repairs.

```sh
mise exec -- cargo build
node tools/parser-oracle/md045.mjs
```

The development oracle passes 183 pinned/native diagnostic and source-preservation
cases. Node is not a runtime dependency.
