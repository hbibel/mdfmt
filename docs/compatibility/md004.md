# MD004 unordered-list markers

MD004 diagnostics and contextual repairs target markdownlint 0.42.0's
`lib/md004.mjs`. Overall coverage remains incomplete; see `rules.json`.

## Behavior

- Supports consistent, dash, plus, asterisk and sublist styles. Invalid style
  values remain schema errors even though the upstream rule source has a fallback.
- Consistent style uses the first unordered marker. Sublist style records a
  global choice per nesting depth, including ordered-list ancestors, and chooses
  a different marker when a new depth's first marker matches its parent choice.
- Disabled reference markers still establish expected styles, matching upstream.
  Individual findings/repairs respect aliases/tags, severity, directives and fix
  permissions.
- Replaces only the one-byte marker, preserving padding, indentation, task
  checkboxes and item content. Every batch must preserve the semantic tree and
  all protected source. List merges and accidental thematic breaks are rejected.
- Marker and thematic-break repairs settle together: either contextual repair
  can make the other rule's initially rejected batch safe. Original-coordinate
  edit reconstruction and second-pass stability are tested.

## Preservation limits

A failed contextual check withholds the entire marker batch. Some upstream fixes
therefore remain diagnostics rather than silently merging separate lists.
Unmodeled HTML/math/directive documents also retain their markers.

Native list ancestry and literal boundaries can differ from upstream around
tabbed container prefixes. MD004 diagnostics use a read-only tab-expanded parse,
with marker spans mapped back to original bytes. Container-relative ancestry
handles changing blockquote indentation without comparing absolute source columns.
The shared parser guard withholds all edits for uncertain tabbed container
prefixes: native tree equality alone cannot establish that the source is not code.

## Evidence

`tests/md004.rs` covers literal safe outputs and unsafe boundaries, ordered and
unordered nesting, global depth selection, permissions, tasks/quotes, BOM/CRLF,
all-rule composition, original edit coordinates and idempotence. It compares
findings with 296 pinned observations, including schema-invalid styles.
CLI tests cover stdout/check/write, preserved-boundary errors and disabled-fix warnings.

```sh
mise exec -- cargo build
node tools/parser-oracle/md004.mjs
```

The development oracle compares diagnostic positions/details, schema errors and
native repair stability. In this corpus, 40 native outputs preserve source that
upstream would fix; literal boundary tests cover the safety reasons. Node is not
a runtime dependency, and full upstream parser parity is not claimed.
